# The demo scene

**Function:** `obia.make_demo_scene(size=160, seed=0)` · **CLI:** `pygeovision obia demo OUTPUT_DIR [--size N] [--seed N]`

## Why

To learn OBIA, or to check that you are using it correctly, you want an image where you **know the right answer exactly**.
Real imagery never offers that: reference data has errors, and digitising takes days. The demo scene is generated by code,
so every pixel's true object and class is known. That lets every page of this documentation show real numbers you can
reproduce in seconds, offline, with no downloads.

It is a **teaching and testing tool, not a benchmark.** The pixel values are artificial, so results on it say how the
*methods behave*, not how well they will do on your imagery.

## How to use

```python
from pygeovision import obia

scene = obia.make_demo_scene()                 # 160 x 160 pixels, seed 0
scene.raster          # RasterData: 4 bands, 2 m pixels, EPSG:32633
scene.reference       # GeoDataFrame of the true objects: ref_id, class, geometry
scene.ref_labels      # (160, 160) int32: true object id per pixel
scene.class_raster    # (160, 160): true class code per pixel
scene.class_names     # ['water', 'forest', 'cropland', 'bare_field', 'building', 'road']
```

```console
$ pygeovision obia demo ./obia_demo --size 160 --seed 0
  ✓ Demo scene (160x160, seed 0) → ./obia_demo
    classes: water, forest, cropland, bare_field, building, road
```

The command writes three files:

| File | Contents |
|---|---|
| `scene.tif` | 4-band float32 image with band descriptions `blue, green, red, nir` |
| `reference.gpkg` | The true objects as polygons, with columns `ref_id`, `class` |
| `reference_ids.tif` | `int32` raster of true object ids (same as `scene.ref_labels`) |

| Argument | Default | Meaning |
|---|---|---|
| `size` | 160 | Width and height in pixels. At least 96, or `ValueError: size must be >= 96` |
| `seed` | 0 | Random seed. A different seed gives a different scene |

## What is in it

A 160 × 160 scene (320 m × 320 m) with 28 true objects:

| Class | Objects | Pixels | Shape | Why it is in the scene |
|---|---:|---:|---|---|
| `cropland` | 7 | 9,201 | Irregular field cells | Green and bright in NIR: easy by colour |
| `bare_field` | 6 | 10,458 | Irregular field cells | Bright in the visible bands, **close to buildings spectrally** |
| `forest` | 2 | 3,194 | Ellipses | Similar mean NIR to cropland but **textured** (high within-object variation) |
| `water` | 1 | 1,443 | Ellipse | Dark in NIR: the easiest class |
| `road` | 1 | 640 | A straight band | Spectrally unremarkable, but **long and thin** |
| `building` | 11 | 664 | Small rectangles | Spectrally like bare fields, but **small and compact** |

The fields are a Voronoi partition, so they have irregular outlines; forest, lake, road and buildings are laid on top.
Counts above are the same for any seed at the default size (the layout and radiometry differ). At `size=96` there are 22
objects, at `size=320` there are 52.

The scene is built so that **colour alone is not enough**:

| Pair | What separates them |
|---|---|
| Forest vs cropland | Texture: forest `std_nir` ≈ 14, cropland ≈ 5 |
| Bare field vs building | Size and compactness |
| Road vs bare field | Elongation (about 20 for the road) |

Mean pixel values per class (blue, green, red, nir; 0–255 scale):

| Class | Blue | Green | Red | NIR |
|---|---:|---:|---:|---:|
| water | 62 | 52 | 37 | 14 |
| forest | 21 | 41 | 24 | 129 |
| cropland | 36 | 81 | 41 | 170 |
| bare_field | 98 | 117 | 138 | 126 |
| building | 108 | 123 | 138 | 117 |
| road | 99 | 98 | 104 | 90 |

(Each object also gets a brightness offset of about ±7, and pixels carry spatially smooth noise, so objects of the same
class are not identical.)

Georeferencing: UTM zone 33N (`EPSG:32633`), 2 m pixels, upper-left corner at (352000, 5297000), near Salzburg. The place
is arbitrary; nothing about the scene is real.

## Typical uses

- **Learn.** Follow the [tutorial](tutorial.md) end to end.
- **Choose a method.** Segment with each method and score against `scene.ref_labels` ([Segmentation](segmentation.md#what-the-results-look-like)).
- **Test a rule or pipeline.** If your code cannot get sensible results here, the problem is in the code.
- **Test generalisation.** Train on `seed=0`, assess on `seed=1`: a new scene, a different layout, the same classes
  ([Accuracy](accuracy.md#the-training-data-trap)).
- **Teach.** Every exercise runs in seconds on a laptop with no data download.

Build a held-out pair like this:

```python
A = obia.make_demo_scene(seed=0)       # build rules / train here
B = obia.make_demo_scene(seed=1)       # assess here
```

## What it cannot tell you

- **It is too clean.** Real scenes have shadows, mixed pixels, seasons, sensor noise and sub-classes. Accuracy on the demo
  is higher than you will usually see.
- **The reference is perfect.** The truth has no errors and is aligned to the pixel. Yours will not be.
- **Classes are few, balanced by design only loosely.** Water has one object and forest two, so per-class results on rare
  classes swing wildly: one object moves a score by 50 points.
- **Region merging suits it.** Flat-coloured objects with sharp edges favour the `multires` method over others.
  Do not infer a ranking of algorithms for real imagery from it.

## What to do when…

| You see | Cause | Do this |
|---|---|---|
| `ValueError: size must be >= 96` | `size` below the minimum | Use 96 or more |
| Two runs give different images | Different `seed` | Fix the seed; the same seed gives an identical scene |
| `scene.reference["class"]` holds `np.str_` values | NumPy string type from `pandas` | Harmless; convert with `.astype(str)` if a library complains |
| `obia demo` writes into a missing folder | The command creates it | Nothing to do |
| Accuracy on another seed is lower than on the first | You trained on seed 0 and look at seed 1 | Expected, and the honest number. See [Accuracy](accuracy.md#the-training-data-trap) |
| Pixel results are nonsense when comparing to `class_raster` | Its codes follow `class_names` order, not the classifier's | Re-map codes ([warning](accuracy.md#pixel-accuracy-pixel_report)) |
| Want a larger or more complex test | The demo is small by design | Use `size=320`, or real imagery with your own reference |
